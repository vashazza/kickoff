# [대회명] — Claude Code 인수인계 문서

> **예시 문서 안내**: 실제 대회에서 쓴 HANDOFF.md를 대회 식별 정보만 마스킹한 것입니다.
> `[대괄호]`는 가려진 값, `N_*`는 가려진 수치입니다. 구조·밀도·문장 방식을 참고하세요.

> 이 파일은 Claude Code가 프로젝트 폴더에서 작업을 시작할 때 가장 먼저 읽는 문서입니다.
> 대회 규칙·데이터 명세의 요약과, 작업 폴더 구성·베이스라인 구축·연구일지 작성 방침을 담고 있습니다.
> 원문 규칙이 필요하면 `docs/` 아래 대회 문서 사본을 참조하세요(아래 §1 참고).

## 0. 한 줄 요약

[도메인] 문서 1건을 입력받아 **K개 검토항목의 위반 여부(v1~vK, 0/1)** 와 **근거 문구(e1~eK, 원문 부분문자열)** 를 출력하는 파이프라인을 만든다.
모델은 고정(파인튜닝 불허), 평가는 위반 클래스 Macro-F1. **첫 목표는 동작하는 베이스라인 submission 1개**.

---

## 1. 작업 시작 시 해야 할 일 (순서대로)

1. 프로젝트 폴더 안의 압축파일(`open.zip` 또는 유사한 이름)을 찾아 `data/raw/`에 해제한다. 압축파일 원본은 삭제하지 말 것.
2. 아래 §4 폴더 구조를 만든다. 이미 있는 폴더는 건드리지 않는다.
3. 대회 문서(규칙·평가방법·데이터 설명·데이터 명세)가 폴더 안에 있으면 `docs/`로 모은다. 없으면 이 문서의 §2 요약을 기준으로 진행한다.
4. `data/raw/baseline/script.py --mock` 을 실행해 입출력 흐름을 확인한다.
5. §5 베이스라인 계획에 따라 `src/`, `scripts/`를 구성하고 dev N_dev건 자가 채점까지 돌린다.
6. 결과를 `logs/research_log.md`에 기록한다(§6 형식).

## 2. 대회 규칙 요약 (반드시 지킬 것)

### 모델
- 고정 LLM: `[고정 LLM 모델 ID]` (리비전 `[커밋 해시]`)
- 보조 임베딩: `[임베딩 모델 ID]` (리비전 `[커밋 해시]`)
- 두 모델은 평가 서버에 준비돼 있음. **제출물에 모델 파일을 넣지 말 것.** 환경변수 `[PREFIX]_MODEL_DIR`, `[PREFIX]_EMBED_DIR`로 로드.
- 평가 서버 하드웨어·이미지·고정 패키지 버전은 `docs/eval_server_spec.md` 참조 ([GPU] [VRAM], [추론 엔진·버전], [torch 버전], Python [버전]).
- 파인튜닝·LoRA·어댑터 불허. 참가자가 학습시킨 가중치(분류기·회귀·추가 임베딩 등)를 판정에 쓰는 것 불허. `model/`에는 RAG 인덱스 같은 정적 자산만.
- **샘플마다 고정 LLM을 최소 1회 "정상 호출"해야 함** — 해당 샘플 내용을 포함한 프롬프트로 호출해 정상 응답을 받아야 함. 규칙만으로 만든 제출물은 무효.
- 후처리·규칙 기반 보정은 자유.

### 데이터
- 허용: 대회 제공 데이터·자료 전부(무라벨 N_unlabeled건, dev N_dev건, `data/` 폴더), 자가 라벨링 전면 허용, 라벨 생성 단계에 한해 외부 LLM 사용 허용(대회 자료만 입력, 웹검색 금지), pip 오픈소스 라이브러리, 코드 공유 게시판 전체 공개 자료.
- 금지: 외부 데이터 수집(원천 플랫폼·공공 API·크롤링), 익명화 식별자 복원, **제출 추론 코드에서 외부 LLM·외부 API 호출**, 데이터 자산 우회 반입, 팀 간 사적 공유.
- 판단 기준이 되는 규정은 배포된 `[규정 패키지]/` 스냅샷으로 고정.
- 평가 데이터로 추가 학습·pseudo-labeling 금지. **샘플 간 독립 예측**(다른 샘플의 정보·통계로 보정 금지). 한 샘플 내 문서 분할 추론은 허용.

### 재현성
- 수상 시 제공 자료 + 제출 자료만으로 점수 재현 검증. 자가 라벨링 코드·프롬프트·사용 모델 버전도 재현 대상. → **라벨 생성 프롬프트와 코드는 반드시 `scripts/labeling/`에 보관.**

### 평가
- 리더보드: v1~vK 각 항목의 위반(=1) 클래스 F1을 단순 평균(Macro-F1). e1~eK는 리더보드 미반영, 2차 정성평가(X%)에 사용.
- Public = 전체 테스트 N_test건 100%. Private = 종료 시점 Public.
- 상위 [M]팀 → 2차 평가(재현 검증 + 근거 문구 정성평가 + 규칙 준수).
- 근거 문구: 원문 부분문자열이 아니면 자동 무효. 대조 대상은 본문 텍스트이고 meta는 대조 대상 아님. 위반 부분만 짧게 인용하는 것이 유리.

### 평가 서버 주의 (베이스라인 script.py가 모두 처리하는 예시)
1. 실행 코드는 `if __name__ == "__main__":` 아래에 둘 것(추론 엔진 멀티프로세싱).
2. 경로 하드코딩 금지 — `[PREFIX]_DATA_DIR`, `[PREFIX]_OUTPUT_DIR`, `[PREFIX]_MODEL_DIR`, `[PREFIX]_EMBED_DIR` 환경변수 사용.
3. 서버는 인터넷 차단 — 모델 ID로 다운로드 시도하면 실패.
4. LLM이 GPU 대부분을 씀 — 임베딩은 CPU 또는 로드 순서 설계 필요.
5. `data/`의 id를 그대로 읽어 `output/submission.csv`로 쓰기. id 접두·건수 하드코딩 금지.
6. 실행 시간 최대 [T]시간.

## 3. 데이터 명세 요약

### 배포 구조 (`open.zip`)
```
README.md
train_unlabeled.jsonl.gz   # 무라벨 N_unlabeled건 (위반 샘플 섞여 있음, 정상 보증 없음)
dev.jsonl.gz               # 라벨 예시 N_dev건
dev_labels.csv             # dev 정답 (제출 형식과 동일)
sample_submission.csv      # 제출 양식
data/
  test.jsonl.gz            # 형식 확인용 소수 건. 서버에서 N_test건으로 교체됨
  [항목 정의].json          # K항목 정의·근거 조문·부재탐지 여부
  [디코딩 스키마].json       # structured outputs용 JSON 스키마
  [규정 패키지]/            # 판단 기준 규정 텍스트 + 품목 대조용 csv
baseline/
  script.py                # 데이터 로드 → 제약 디코딩 추론 → 근거 검증 → submission.csv
  requirements.txt
```

### 레코드 (jsonl 한 줄 = 샘플 1건)
| 키 | 내용 |
|---|---|
| `id` | 샘플 식별자. 제출 id로 그대로 |
| `docs` | `[{doc_id, type, text}]` — type: [문서 유형 A·B·C…]. 표는 `\|` 로 복원. 주 문서는 항상 1건 이상 |
| `meta` | 원천 플랫폼 등록 정보 N_meta필드 |
| `dropped_doc_counts` | 길이 예산 초과로 제외된 문서 종류·개수. 비어있지 않으면 첨부 일부 누락 → 부재탐지형 판정 주의 |
| `input_completeness` | bool 플래그들: 주 문서 실재·추출 성공·무탈락·완전관측 |
| `anon_applied` | 전건 true |

### meta 필드
[N_meta개 필드 — 적용 규정 구분, 계약/조달 방식, 금액, 지역·업종 제한, 일자 등]

- 값 없음 = `null`, 등록 안 됨 = `"미입력"`. 둘 다 "해당 없음"이 아님.
- 본문 기재값과 meta가 다르면 **적용 규정·금액 구간은 본문 기재값 우선**, 본문에 없으면 meta 기준. 불일치 자체는 별도 항목(vK) 판정 대상.
- 익명화 토큰: `[기관(유형)|지역=r1]` 형태로 기관 유형·지역 비교에 필요한 정보만 남김. 금액·수량·날짜·조문·품명·규격은 원문 유지.

### K개 항목 (◽ = 부재탐지형, 근거 문구 항상 빈칸)
| 번호 | 유형 | 적용 조건(게이팅) 예 |
|---|---|---|
| v1~v4 | 참가자격 제한 | 금액 구간별 |
| v5~v8 | 지역 제한 | 금액 구간·지역 단위별 |
| v9 | 본문 특정 표현 명시 | 특정 첨부 문서에만 |
| v10 ◽, v11 ◽ | 필수 조건 **누락** | 특정 품목군일 때만 |
| … | … | … |
| vK | 본문과 meta 입력값 상이 | 항상 |

### 제출 형식 (`output/submission.csv`)
- 열: `id, v1~vK, e1~eK`. 열 순서는 sample_submission.csv와 동일. 행 수 = 입력 건수.
- v: 정수 0/1만 (true·"1" 불가). 판단 어려워도 0으로 채움, 빈칸 금지.
- e: 위반 시 원문 부분문자열 그대로, [L]자 이하, 비위반은 빈칸, 부재탐지형 항목의 e는 항상 빈칸.
- UTF-8(BOM 없음) · NFC · RFC4180 quoting · 셀 첫 글자 `= + @` 금지.

## 5. 베이스라인 계획 (1차 목표)

목표: **dev N_dev건에서 채점되고, --mock으로 submission.csv가 나오는 파이프라인**. 점수보다 형식·재현·흐름 우선.

### 설계 원칙
LLM에 판정을 통째로 맡기지 않는다. **적용 가능성은 코드(meta·품목 csv)로 결정, LLM은 본문에서 사실·문구 추출, 최종 0/1은 후처리 규칙으로 확정.**

### 단계
1. **`io.py`**: jsonl.gz 로드, `sample_submission.csv` 열 순서로 DataFrame 생성, 형식 검증 함수(정수 0/1, 빈칸, 길이 제한, 수식 접두, NFC, 행 수·id 일치).
2. **`meta.py`**: 금액 파싱(본문 기재값 우선 → meta), 금액 구간 분류(기준 금액은 `[항목 정의].json`·규정 패키지에서 확인), 적용 규정 구분, 계약 방식, 지역 제한 여부, 품목 코드 ↔ 품목 csv 대조 결과.
3. **`rules.py`**: 항목별 `applicable(record) -> bool` 게이팅. 예: 특정 계약 방식에서만 적용되는 항목, 특정 품목군에서만 적용되는 항목, 금액 구간별 항목. 게이팅 실패 항목은 LLM 질의 없이 0 고정.
4. **`prompts.py` + `llm.py`**: 적용 가능한 항목만 묶어 1회(또는 항목 그룹별 수회) 호출. 프롬프트는 "해당 문구가 있으면 원문 그대로 인용" 형식, `[디코딩 스키마].json`으로 제약 디코딩. `--mock`이면 전부 0/빈칸 반환.
   - **매 샘플마다 최소 1회는 반드시 본문을 포함해 호출**(규칙 요건). 게이팅으로 항목이 하나도 안 남아도 호출은 수행.
   - 긴 문서는 문서 단위로 나눠 호출하고 결과를 OR 병합.
5. **`evidence.py`**: LLM 인용문이 `docs[*].text` 부분문자열인지 검증. 아니면 근거 빈칸 처리(v는 유지할지 규칙으로 결정). 길이 초과는 위반 핵심부만 남기도록 트리밍. 부재탐지형은 무조건 빈칸.
6. **`metrics.py` + `scripts/eval_dev.py`**: dev_labels.csv와 대조해 항목별 precision/recall/F1과 Macro-F1 출력. 규칙만(LLM off) 점수와 규칙+LLM 점수를 각각 기록.
7. **`scripts/build_submit.py`**: submit.zip 생성 후 `--mock`으로 로컬 실행 검증.

### 로컬 환경 주의
- 로컬에 고정 LLM을 띄울 GPU가 없으면 `--mock`과 규칙 기반 경로로 개발·채점하고, LLM 부분은 프롬프트·스키마만 준비해 둔다.
- 자가 라벨링에 외부 LLM을 쓸 경우 `scripts/labeling/`에 프롬프트·모델명·버전·실행 스크립트를 남기고, 산출 라벨은 `data/labels/`에 저장한다.

## 6. 연구일지 방침 (`logs/research_log.md`)

**실험이 진행될 때마다** 아래 형식으로 항목을 추가한다. 코드 변경만 있고 결과가 없으면 "변경 사항"만 적어도 된다. 가장 최근 항목이 위로 오도록 역순 기록.

```markdown
## [YYYY-MM-DD] exp_NN — 한 줄 제목

**목적**: 무엇을 확인하려 했는가
**변경 사항**: 코드/프롬프트/규칙에서 바뀐 것 (파일 경로 포함)
**설정**: 데이터(dev/자가라벨 n건), LLM on/off, 호출 방식, 시드 등
**결과**:
| 지표 | 값 |
|---|---|
| Macro-F1 (dev) | 0.xxx |
| 항목별 최저 3개 | vX 0.xx, vY 0.xx, vZ 0.xx |
| 실행 시간 | |
**관찰**: 잘 된 것 / 안 된 것 / 오류 패턴
**다음 할 일**:
**산출물**: output/exp_NN/ 경로
```

파일 상단에는 실험 번호·날짜·Macro-F1·한 줄 요약을 담은 **요약 표**를 유지하고, 항목 추가 시 표도 갱신한다.
