# 대회·해커톤 제약 추출 체크리스트

각 항목마다 원문에서 근거를 찾아 constraints.yaml에 넣는다. 원문에 없으면 open_questions로.
★ 표시는 traps 후보가 자주 나오는 곳 — 특히 꼼꼼히 읽는다.

## 과제
- [ ] 입력 단위와 출력 단위 (샘플 1개 = 무엇, 출력 = 무엇)
- [ ] 라벨/클래스 정의, 클래스별 판정 기준 문서(항목 정의서)
- [ ] 첫 마일스톤으로 삼을 "동작하는 최소 제출물"

## 모델·방법 ★
- [ ] 고정 모델이 있는가 (모델 ID, 리비전/해시, 로드 방식)
- [ ] 파인튜닝·LoRA·어댑터·추가 학습 가중치 허용 여부
- [ ] 사전학습 가중치·외부 모델 사용 가능 범위 (라이선스, 공개 시점 제한)
- [ ] ★ "모델을 반드시 써야 한다"는 최소 사용 조건 (예: 샘플마다 LLM 1회 호출)
- [ ] 앙상블·후처리·규칙 기반 보정 허용 여부

## 데이터 ★
- [ ] 제공 데이터 목록·건수·라벨 유무
- [ ] 외부 데이터 허용 범위 (크롤링, 공개 데이터셋, API)
- [ ] 자가 라벨링·의사 라벨링 허용 여부, 외부 LLM으로 라벨 생성 가능 여부와 조건
- [ ] ★ 테스트 데이터 사용 제한 (학습 금지, pseudo-label 금지, 샘플 간 독립 예측)
- [ ] 익명화·비식별 토큰 규칙과 복원 금지
- [ ] null / 미입력 / 해당없음처럼 결측의 의미가 다른 값

## 평가 ★
- [ ] 지표 정의 (평균 방식: macro/micro/weighted, 양성 클래스만인지)
- [ ] Public/Private 분할 비율, 최종 순위 기준
- [ ] 2차 평가(정성평가, 발표, 코드 검증) 비중과 대상
- [ ] 로컬에서 지표를 재현할 방법 (dev/val 셋, 정답 파일)

## 제출 형식 ★
- [ ] 파일명·경로·열 순서·행 수 규칙
- [ ] 값 타입 (정수 0/1, 문자열, 빈칸 허용 여부)
- [ ] 인코딩·정규화·quoting·특수문자 금지 규칙
- [ ] 제출 패키지 구조 (zip 안 파일, requirements, 진입점)
- [ ] 제출 횟수 제한, 최종 제출 선택 방식

## 실행 환경 ★
- [ ] 평가 서버 하드웨어·VRAM·고정 패키지 버전·Python 버전
- [ ] 실행 시간 제한, 메모리 제한
- [ ] 인터넷 차단 여부 (모델 다운로드 시도 = 실패)
- [ ] 경로 규칙 (환경변수, 하드코딩 금지)
- [ ] 진입점 규칙 (`if __name__ == "__main__":` 등 멀티프로세싱 주의)
- [ ] id·건수 하드코딩 금지, 샘플 파일과 실제 테스트 건수 차이

## 재현성·검증 ★
- [ ] 수상 시 재현 검증 범위 (코드, 라벨 생성 과정, 프롬프트, 모델 버전)
- [ ] 제출해야 하는 부속 자료 (보고서, 코드 저장소)
- [ ] 팀 구성·코드 공유 규칙 (공개 게시판, 팀 간 사적 공유 금지)

## 일정
- [ ] 최종 제출 마감, 팀 병합 마감, 2차 평가 일정
