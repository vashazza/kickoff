# 연구 실험 프로젝트 제약 추출 체크리스트

입력 문서는 보통 제안서·지도교수 메일·선행 논문·데이터셋 카드·투고처 안내다. 대회와 달리 규칙이 흩어져 있으니,
문서에서 못 찾은 항목은 `interview.md` 순서로 짧게 물어본다(사용자만 아는 것이 많다). ★는 traps 후보.

## 연구 질문
- [ ] 연구 질문을 한 문장으로 (무엇을, 무엇과 비교해, 무엇으로 측정)
- [ ] 가설과 각 가설의 반증 조건 (`falsified_if`) — 결과를 보기 전에 적는다
- [ ] 성공 기준: 어떤 결과면 논문이 되고, 어떤 결과면 방향을 바꾸는가
- [ ] 기여 주장(contribution) 후보 2~3개

## 비교 대상
- [ ] 베이스라인 목록과 출처(논문·코드·체크포인트)
- [ ] ★ 베이스라인 숫자를 논문에서 가져올지 직접 재현할지 (설정이 다르면 비교 불가)
- [ ] ablation으로 확인할 구성요소

## 데이터 ★
- [ ] 데이터셋 이름·버전·접근 방법·라이선스 (재배포·상업적 사용·논문 게재 조건)
- [ ] ★ 공식 split 유무, test 셋 사용 시점 (튜닝에 test 사용 금지)
- [ ] ★ 누수 위험: 환자/피험자 단위 분리, 시간 순서, 중복 샘플, 사전학습 데이터와의 겹침
- [ ] IRB·개인정보·기관 반출 제한 (의료 데이터면 필수 확인)
- [ ] 전처리 결정 중 결과에 영향이 큰 것

## 평가 프로토콜 ★
- [ ] 주 지표와 보조 지표, 해당 분야에서 표준인 지표
- [ ] 시드 수, 반복 횟수, 신뢰구간·통계 검정 방법
- [ ] ★ LLM 평가라면: judge 모델·버전 고정, 프롬프트 버전 관리, temperature, 위치 편향 대책
- [ ] 사람 평가가 있다면: 평가자 수, 일치도 지표, 블라인드 여부

## 자원·환경
- [ ] 사용 가능한 GPU·서버·스토리지, 주당 가용량
- [ ] API 비용 한도 (외부 LLM 사용 시)
- [ ] 코드·데이터를 둘 위치 (랩 서버, 개인 머신), 동기화 방식

## 재현성
- [ ] 환경 고정 방식 (uv/conda lock, Docker)
- [ ] 설정 관리 (configs/*.yaml, 실험마다 설정 스냅샷 저장)
- [ ] 체크포인트·산출물 보관 규칙과 용량
- [ ] 코드 공개 계획 (투고 시 익명 저장소 필요 여부)

## 일정·산출물
- [ ] 투고처와 마감 (초록 마감과 본문 마감이 다른지), 페이지 제한
- [ ] 중간 보고 일정 (랩 미팅, 지도교수 리뷰)
- [ ] 결과 → 논문 표/그림 매핑 초안 (`result_map`)
